## 1. 背景と目的

### 1.1 背景
現在、`HorizonCyclingBridge` は Forza Telemetry UDP 受信（1秒毎のデバッグ出力）、Bluetooth LE (FTMS / Cycling Power) の status メッセージ、およびスマートローラーへのコマンド送信通知を `Console.WriteLine()` や `Console.Write("\r...")` で順次コンソールに出力しています。
その結果、ログが数秒おきに流れるように下方向へスクロールし続け、ライディング中・テスト中に「現在のペダル出力（W）」「現在速度/目標速度（km/h）」「道路勾配（%）」「アクセル・ブレーキ出力（%）」といった重要なリアルタイム数値を直感的に把握することが困難になっています。

### 1.2 目的
コンソール画面の表示領域を固定化（ダッシュボード化）し、以下の効果を達成します。
1. **視認性の飛躍的向上**: リアルタイムな走行データやシステムステータスを画面上の決まった位置に常時表示・更新する。
2. **操作性の向上**: 操作可能なキーガイド（難易度調整 `+/-`、モード切替 `M`、テスト `T`、終了 `Q`）を常に視界に入る位置に固定配置する。
3. **ログの整理**: BLE接続メッセージやシステムイベントログを独立したログ表示枠に収め、リアルタイム描画を破壊しない構造とする。

## 2. 画面レイアウト設計 (UI Wireframe)

コンソール画面（標準80桁×25行以上）を**3つの固定ゾーン**に分割します。

### ゾーン別詳細仕様

| ゾーン名称 | 行数目安 | 内容 | 更新頻度 |
| :--- | :--- | :--- | :--- |
| **1. Header & System Status** | 行 1〜8 | アプリ名、現在の動作モード、BLE接続状態、vJoy状態、Telemetry受信状態 | イベント発生時（接続切断やモード変更時） |
| **2. Realtime Metrics** | 行 9〜15 | ペダル出力(W)、実車速/目標車速(km/h)、生勾配/送信負荷勾配(%)、Trainer Difficulty(%)、Throttle/Brake出力(%) | リアルタイム（100ms〜1000ms周期） |
| **3. Key Instructions** | 行 16〜21 | 利用可能なキー操作の説明一覧 | 固定表示 |
| **4. Event Log Region** | 行 22〜28 | 直近のイベントログ（最大5〜8件）。新しいログが入ると枠内でスクロール | イベントログ発生時 |

## 3. 技術アプローチの比較と選択

画面固定化（ダッシュボード化）の実現方法として以下の2案を検討します。

### 案A: C# 標準 `Console.SetCursorPosition` 方式 (推奨)
- **概要**: 外部パッケージを追加せず、.NET 標準の `Console.SetCursorPosition(x, y)` または ANSI エスケープシーケンス `\x1b[H` を利用して画面上の特定座標にカーソルを移動させ、値を上書き更新する。
- **メリット**:
  - 追加の依存ライブラリ（NuGet）が不要。
  - 軽量で動作が非常に安定しており、パフォーマンス負荷が極めて低い。
  - カスタマイズが容易。
- **デメリット**:
  - コンソールウィンドウのサイズ変更時に表示が崩れる可能性がある（画面サイズ取得・クリアロジックでカバー可能）。

### 案B: `Spectre.Console` TUI ライブラリ導入方式
- **概要**: NuGet パッケージ `Spectre.Console` を追加し、`LiveDisplay` や `Table` / `Panel` レイアウトコンポーネントを使用してモダンなダッシュボードを構築する。
- **メリット**:
  - 見栄えが非常に美しい（リッチなカラー、枠線、グラフィカルな表示）。
- **デメリット**:
  - 外部ライブラリ依存が発生。
  - 非同期イベント（UDP受信、BLE通知、キー入力）との連携描画でスレッド排他制御の配慮が必要。

> **判定方針**:  
> 本プロジェクトのシンプル性と軽量さを維持するため、**「案A (標準 Console.SetCursorPosition + 排他ロック)」** を基本実装方針として推奨します。ただし、将来的に見た目の美しさを優先する場合は 案B への拡張も考慮可能なモジュール構造とします。

## 4. 詳細設計・アーキテクチャ

### 4.1 新設クラス: `ConsoleDashboard`

画面描画ロジックを `Program.cs` から分離し、専用のダッシュボード管理クラス `ConsoleDashboard` を作成します。

```csharp
namespace HorizonCyclingBridge.Core
{
    public class ConsoleDashboard
    {
        private readonly object _lockObj = new object();
        private readonly Queue<string> _logBuffer = new Queue<string>();
        private const int MAX_LOG_COUNT = 6;

        // システム情報プロパティ
        public string ModeName { get; set; } = "SIMULATION MODE";
        public string BleStatus { get; set; } = "Disconnected";
        public bool IsVJoyActive { get; set; }
        public bool IsTelemetryActive { get; set; }

        // リアルタイムメトリクス
        public double CurrentPower { get; set; }
        public double TargetSpeedKmh { get; set; }
        public double CarSpeedKmh { get; set; }
        public double RawGrade { get; set; }
        public double SentGrade { get; set; }
        public double Difficulty { get; set; }
        public double Throttle { get; set; }
        public double Brake { get; set; }

        public void InitializeLayout()
        {
            lock (_lockObj)
            {
                Console.Clear();
                Console.CursorVisible = false;
                DrawStaticFrame();
            }
        }

        public void UpdateMetrics()
        {
            lock (_lockObj)
            {
                // 特定座標に移動してメトリクスのみを更新
                WriteAt(21, 10, $"{CurrentPower,5:F0} W");
                WriteAt(56, 10, $"{TargetSpeedKmh,5:F1} / {CarSpeedKmh,5:F1} km/h");
                WriteAt(21, 11, $"{RawGrade,+5:F1} %");
                WriteAt(56, 11, $"{SentGrade,+5:F1} %");
                WriteAt(21, 12, $"{Difficulty * 100,5:F0} %");
                WriteAt(56, 12, $"{Throttle * 100,3:F0} % / {Brake * 100,3:F0} %");
            }
        }

        public void AddLog(string message)
        {
            lock (_lockObj)
            {
                string timestamp = DateTime.Now.ToString("HH:mm:ss");
                _logBuffer.Enqueue($"[{timestamp}] {message}");
                while (_logBuffer.Count > MAX_LOG_COUNT)
                {
                    _logBuffer.Dequeue();
                }
                RedrawLogs();
            }
        }

        private void WriteAt(int x, int y, string text)
        {
            Console.SetCursorPosition(x, y);
            Console.Write(text);
        }

        private void RedrawLogs()
        {
            int startY = 22;
            int index = 0;
            foreach (var log in _logBuffer)
            {
                Console.SetCursorPosition(2, startY + index);
                // 行全体を空白でクリアしてから書き込み
                Console.Write(log.PadRight(76).Substring(0, 76));
                index++;
            }
        }

        private void DrawStaticFrame()
        {
            // 枠線や静的テキストの一括描画
        }
    }
}
```

### 4.2 スレッドセーフと排他制御
- Forza UDP 受信スレッド、BLE イベントスレッド、キー入力メインループの異なるスレッドから描画要求が発生します。
- 全ての `Console.SetCursorPosition` および `Console.Write` 呼び出しは `lock (_lockObj)` で排他保護し、表示の崩れやカーソル位置の衝突を防ぎます。

### 4.3 ログのリダイレクト
既存の `Console.WriteLine(...)` 呼び出しを以下のように打ち替えます。

- **定期デバッグ情報（テレメトリデータ）**: 画面上の `Realtime Metrics` エリアのプロパティ更新（`dashboard.UpdateMetrics()`）に集約。
- **イベントメッセージ（BLE接続、難易度変更、モード変更）**: `dashboard.AddLog("...")` にてログ枠へ追加。

## 7. 確認および補足事項

1. **画面サイズ**
   - コンソールウィンドウの推奨サイズは **横 80 文字 × 縦 30 行** 以上とします。
2. **終了処理**
   - アプリ終了時（`Q` キー押下時または例外発生時）には `Console.CursorVisible = true` に戻し、カーソル位置を最終行へ移動して安全に終了します。
